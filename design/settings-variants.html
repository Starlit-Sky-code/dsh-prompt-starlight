方案 A · 卡片流 —— 五张卡片自上而下：总开关 / 改写形态 / 内置规则 / 自定义规则 / 模型与高级。
  • 首屏能看到开关 + 形态 + 规则前两组，屏幕短时需滚动。
  • 卡片自带边界，新手最友好：一眼知道「这一块在配什么」。
  • 信息密度最低，纵向最长 —— 与 DSH 其他设置页的「行式」风格差异最大。
  • 实现：单列容器 + 5 个 <section>，改动最小。
方案 B · 左轨分页 —— 在 564px 里再切一刀：左侧 132px 竖向索引，右侧只渲染当前分区。
  • 每屏只有一件事，几乎不用滚动；规则页一屏放得下 11 条。
  • 顶部用一条进度式提示（规则 9/11）让索引本身携带状态。
  • 风险：DSH 外层已有 188px 导航，这里再加一条竖排索引 = 双层导航；我用「细圆点 + 无图标」压低了视觉重量，但仍是三版里最"重"的结构。
  • 实现：多一个状态（当前分区）+ 分区切换，代码量最大。
方案 C · 紧凑行 —— 单列行式：一行一个设置项，左侧标题+说明、右侧控件；完全对齐 DSH 原生设置页的行式语言。
  • 密度最高：564px 内一屏能看到开关 + 形态 + 规则全 11 条。
  • 与 DSH 自带的「通用设置」长得一样，最不像外挂；规则说明压缩成 10.5px 小字或省略。
  • 代价：解释文案空间小，复杂项（规则为什么建议保留）只能靠 title 悬停。
  • 实现：行容器 + 右侧控件，代码量最小，也最容易做 @container 响应。

三版对比
A · 卡片流B · 左轨分页C · 紧凑行
信息架构 单列纵向，五张卡片 左侧索引 + 右侧单分区 单列行式，小节分组
首屏可见 开关 + 形态 + 规则第一组 当前分区的全部内容（不滚动） 开关 + 形态 + 规则全 11 条
564px 内密度 低（卡片留白多） 中（左侧占 132px） 最高
与 DSH 原生设置的一致度 低（卡片语言） 中（双层导航需克制） 高（行式，与「通用设置」同源）
新手可读性 高（每块都有说明位） 高（一次只看一件事） 中（说明压缩到 11px / title）
要滚动多少 最多（约 1.6 屏） 最少（分区内基本不滚） 少（约 1.1 屏）
实现成本 低：5 个 section + 卡片壳 高：多一层分区状态与切换 低：行容器 + 右侧控件
以后加设置项 向下追加卡片，页面更长 加进某个分区，几乎不增加长度 加一行，长度线性增长

我的建议：如果希望「一眼就像 DSH 自带的设置」，选 C； 如果更看重「新手能读懂每条规则在干什么」，选 A； B 的结构最优雅但要接受页面里出现第二层导航，而且它把「概览」做成了首页， 等于多设计了一屏。
也可以折中：C 的骨架 + A 的规则区（行式排版，规则区展开成两列带说明）—— 说一声我就按这个做。
